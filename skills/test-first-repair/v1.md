# Test-first repair

Work the failure, not the guess.

1. Before editing anything, run the tests the task names and read
   the failure in full — the assertion, the values, the call path.
   The repair you owe is the one that failure describes.
2. Form the smallest hypothesis that explains the failure: which
   input, which branch, which boundary. If the failure does not
   point at a cause yet, read the code the traceback names before
   widening the search.
3. Make the repair at the cause. Do not adjust the test, do not
   special-case the failing input, and do not silence the symptom
   downstream of where it is produced.
4. Re-run the same tests. The work is done when the failure that
   opened it passes and the rest of the named set still passes —
   not when the edit merely looks right.
