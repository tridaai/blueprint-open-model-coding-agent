# Minimal-diff discipline

The patch is the deliverable; its size is part of its quality.

1. Change only what the task names. A line the task did not ask
   about stays byte-for-byte as it was, however improvable it
   looks — improvements nobody requested are reviewed by nobody.
2. No opportunistic refactors, no renames, no import tidying, no
   reformatting. If the repair needs a helper, add the smallest
   one, beside the code that uses it.
3. Match the file's existing style — naming, error shapes, comment
   density — so the diff reads as the codebase's own hand.
4. Before finishing, re-read the diff as a reviewer would: every
   hunk should be traceable to a sentence of the task. A hunk
   that is not, comes out.
